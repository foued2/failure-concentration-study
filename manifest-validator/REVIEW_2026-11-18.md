# Technical review — manifest-validator v0.2.0

**Date:** 2026-11-18
**Object:** `manifest-validator/` as delivered on 2026-11-18, reviewed against
`../GPT_ADJUDICATION_MANIFEST_VALIDATOR_V0.1_2026-11-17.md` §4 and corrections A–I.
**Method:** read the implementation line by line, probe it adversarially, then re-run the
suite. Findings below are defects found in the delivered code, not restatements of it.

## Findings

| # | Severity | Finding | Disposition |
|---|---|---|---|
| F1 | High | Correction E requires the manifest to **echo the ceiling values exactly**. v0.2.0 only echoed `limits_id`, so a manifest could silently disagree with the authority on every ceiling while still validating. | Fixed: `limits_echo` is now required and every ceiling is compared; disagreement raises `LIMITS_ECHO_VALUE`. Fixture `limits_echo_mismatch_values.json` exercises it. |
| F2 | Medium | A record with a missing or malformed digest entered the duplicate-bucket dictionaries with key `None`; sorting mixed `None`/`str` keys raised `TypeError`, which the top-level handler converted to `INTERNAL_ERROR`. The malformed manifest was still rejected, but the diagnostic error was **masked**, and the report could hide which record was at fault. | Fixed: non-string digests are skipped in duplicate resolution, so the schema error survives into the report. |
| F3 | Medium | Correction G's placeholder scan covered identifiers, enums and digests but **not `settings` values**. A variant with `{"threshold": "TBD"}` passed as a real realization setting and could satisfy the settings-difference condition. | Fixed: sentinel values in machine-readable settings are rejected. Fixture `settings_placeholder.json`. |
| F4 | Low | `variants_realized` counted alias records, conflating "built and diagnosed" with "independent evidence". A reader could over-count support. | Fixed: `variants_independent` added; `variants_realized` keeps its lifecycle meaning and the README states it. |
| F5 | Low | Malformed JSON exited 2 with no file path. | Fixed: the path is included. |
| F6 | Info | The pair witness re-checks source and artifact distinctness that alias resolution already enforces within a parent-cell. | Kept deliberately: the witness is the explicit, auditable statement required by correction F; redundancy is documented rather than removed. |

## Verification after the changes

- Fixtures: 23 synthetic manifests, 8 adversarial (no settings variation, no concentration
  variation, duplicate coordinate, shared source digest, cross-parent digest, zero-failure
  convention, settings placeholder, echo mismatch).
- `py -3 run_tests.py`: **166 checks pass, 0 fail, 0 skip.** The `jsonschema` cross-check
  executed (the package is installed), so the shipped JSON Schema was checked against an
  independent draft 2020-12 implementation for every valid fixture.
- Determinism: two independent CLI invocations produce byte-identical reports, each
  carrying the SHA-256 of the manifest, limits file, schema and validator.

## Not established by this review

1. **Specification fidelity.** The adjudication document is in this repository; the
   authoritative population specification (v0.21) is not. Encoded choices that come from
   the adjudication alone — operator classes `OC-A..OC-D`, the `(q, Z, k_unresolved,
   k_fail)` cell key, the `k_fail >= 2` qualification floor and the "five matched
   versions per parent" assumption — cannot be verified here against the specification of
   record. This must be checked by whoever holds v0.21. A passing suite enforces the
   encoding, not the source rule.
2. **Study existence.** The validator evaluates a manifest. No manifest exists in this
   repository, no parent population is allocated, and A2 is untouched. `M1-si REALIZED`
   on a synthetic fixture is a statement about that fixture.

## Addendum 2026-11-18 (v0.2.1) — source hashing rule

F8 (Medium): the validator reported a single SHA-256 of its own file and of each input.
On a Windows checkout that digest is CRLF-dependent, so it cannot establish source
identity against the stored Git blob (LF), and two readers could report different
"identical" sources.

Fixed: every digest is reported twice — `sha256_canonical` over CRLF->LF normalised
bytes (the identity value) and `sha256_working` over the bytes actually read. The
decision and cell report are asserted byte-identical for CRLF and LF copies of the same
manifest. Suite: 169 checks.
