Revision 2 of this package (this commit)
----------------------------------------
An omitted-intersection defect in h_joint_cons was found by GPT's review of the
Revision 1 package and confirmed by independent exact enumeration:

  - Defect: the inclusion-exclusion over the 5 failure atoms
    F1={tra=0}, F2={trb=0}, F3={tra+trb<=7}, Q1={tea<=7}={tra>=a-7},
    Q2={teb<=7}={trb>=b-7} treated F3&Q1, F3&Q2 and the conditional
    triples F1&F3&Q2, F2&F3&Q1, F3&Q1&Q2 as structural zeros for every
    a,b>=8. They are empty only when a>=15 / b>=15 / a+b>=22 respectively.
    The omitted PAIR probabilities dominate the omitted TRIPLES (each
    triple is a subset of a pair), so the union was overstated and small
    h values could clamp to exactly 0.0.
  - Counterexample (exact, verifiable): a=9, b=15, o=126, NTR=112, where the
    only fully-feasible success state is (tra,tb)=(1,7): the published return
    was 0.0; the correct value is ~2.1451655e-07.
  - h_joint_lib is NOT affected (its G1={tra=a} makes every intersection
    containing F3 impossible for a>=8); unchanged in this revision.

Fix and hardening (this revision):

  - a1_support_comparison.py: h_joint_cons rebuilt with the exact
    emptiness guards (adds s3q1, s3q2, t13q2, t23q1, t3q1q2); comments and
    docstring corrected. Everything else in the module is byte-for-byte
    the Revision 1 logic.
  - run_a1.py: new section 5b regression - direct success-event

      * full recomputation of every joint2 value at N=113 and N=150

  - run_a1.py: out/a1_report.md and out/a1_tables.json are now written
    with explicit encoding="utf-8" (the report's em dash was previously
    written through the Win32 locale as cp1252 0x97 - an encoding defect,

    as a console tee (UTF-8, LF).

Interpreter
-----------
RevF (review/revf-package) pins CPython 3.14.0, standard library only. This is
satisfied by the repository .venv (pyvenv.cfg: version_info = 3.14.0). The
regenerated outputs above were produced under the pinned interpreter. A
re-run under another CPython 3.14.x may differ in the last ulps of floats;
sub-1e-11 differences are within the tests' own tolerances. Verifiers should
still run the pinned interpreter and confirm the report/JSON hashes below.
Byte stability is expected for out/a1_report.md and out/a1_tables.json on
the pinned Windows setup; cross-platform checks are numerical, not byte
comparisons.

run.log provenance
------------------
Since this revision, run.log is written by run_a1.py itself: the script
tees stdout to out/run.log (UTF-8, no BOM, LF line endings). Because the
log contains wall-clock timing tokens ("(0.1s)" etc.), it is NOT
byte-stable across runs; a verifier must compare log CONTENT with timing
tokens ignored or normalized. Report and JSON are static text and are
byte-stable on the pinned interpreter.

Historical note (Revision 1, superseded): the first log was captured via a
PowerShell ">" redirect (UTF-16LE, BOM FF FE, 9002 bytes,
20A96A216E64D9E6B7D9B4A364ACA8741D520F10EF9FE54E3BD32730A0979CA8) and
published after re-encoding to UTF-8 no-BOM CRLF (4500 bytes,
A9C4FBF91F25E002B2F05AAC566D6FCE48AA909955BB2ED80174EC671553949C).
That capture corresponds to the pre-fix Revision 1 outputs.

Validation procedure for the verifier
-------------------------------------
  1. Confirm file scope: exactly the five files above; no __pycache__;
     v03p/a1/.gitattributes (* -text) present so blobs are byte-exact.
  2. Recompute SHA-256 and byte counts of the five files; compare to the table.
  3. Run under the pinned interpreter (<repo>/.venv/Scripts/python.exe,
     CPython 3.14.0) from v03p/a1/; expect exit 0 and "FAILURES: none";
     compare out/a1_report.md and out/a1_tables.json bytes to the published
     hashes; compare run.log content ignoring the timing tokens.
  4. Independently (optional but recommended, as GPT did in review): enumerate
     the direct success event for (a=9, b=15, o=126, NTR=112) and confirm
     h_joint_cons returns ~2.1451655e-07 (any value within 1e-11 of it), not 0.

Carried caveats (from out/a1_report.md; not new claims)
------------------------------------------------------
  - N_b = fixed count of unique valid bodies; 113/450 are rho=0.25 plug-in
    proxies for expected unique counts; validity and duplicate losses are
    unmodeled. Fixed-unique-count is a genuine approximation; NO directional
    (optimistic) claim is established without the count distribution and the
    shape of p(n).
  - S2 middle-region mass is 0.357 at k=5 and 0.0 at k=10 and k=20, i.e. the
    middle can be empty; at k=20 the candidate strata are C=0.2 vs C=0.25.
    Thresholds are stated on attainable z; strata are reported in C. The
    z -> C mapping is defined in the module docstring.
  - Any "best" value requires a stated optimization domain (all enumerated
    rules vs the designated non-vacuous subset). At c-hist @ N=150: maximum over
    all rules is S1-m2 = 7.52e-4; S1-m4 = 3.76e-4. The RevF O4 cell at 3.8e-6 is
    a different reference and is not a substitute for either.
